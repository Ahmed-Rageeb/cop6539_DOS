Pastry: routing hops versus network size

COP6539 Project 3. Ahmed Rageeb Ahsan, Saiful Islam

Each peer is an Erlang actor. Every peer makes two lookups for random stored objects, and we count how many hops each lookup takes before it is delivered. Networks of up to 5,000 nodes are averaged over three runs, the larger ones are a single run.

measuredlog16(N)

Results

The number of hops grows with log N, which is what Pastry is supposed to give. Since the x axis is on a log scale, this shows up as a straight line. Going from 10 nodes to 100,000 nodes only adds about three hops.

From 100 nodes up, the average is at or a little below log16N at every size. This makes sense because log16N assumes we fix one hex digit per hop, but once the key is in range of the leaf set the last few digits are done in a single hop. The Pastry paper reports the same thing.

All lookups found their object, 413,280 out of 413,280 over all runs. We also tested the routing on its own. For each test key we found the closest node by checking every node id, and every lookup ended at that node.

Largest network

The largest network we ran had 100,000 nodes. 200,000 out of 200,000 lookups were found, with an average of 3.96 hops (log16N = 4.15). On our 8 GB laptop the limit was the time it takes to join the nodes one by one, not memory.
